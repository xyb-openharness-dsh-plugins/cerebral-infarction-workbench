# UI 设计要求（M1/M2）

状态：交互规范初稿，待M2原型预览和用户签认。目标情绪：平静、可信、行动明确；急迫来自清楚的呼救动作，不用恐吓/倒计时。

## 信息层级与布局

1. 首页顶部保留暂定品牌和版本 `0.1.0`；首屏第一动作是“疑似卒中？立即联系当地急救服务”，不被导航、资料档案或AI入口挤走。
2. 呼救主按钮需大触控区域、键盘可达、具文字标签；颜色之外同时用图标/文字说明。只在中国大陆配置确认后显示“120”。
3. FAST/中风120 与平衡、视力等症状说明在次级区域；不把“按项目自测”设计成筛除步骤，明确任何一项突发症状都应求助。
4. 急救交接卡只在呼救动作后出现，显示“可选，不能延迟呼救”；每个字段可跳过或选“未知”；不默认保存到患者档案。
5. 稳定期“整理资料”在独立次级入口，避免与急症主动作同等视觉权重。

## 状态与无障碍

- 默认/空：交接卡为空，呼救入口仍完整可见。
- 输入中：退出或浏览器返回不擦除已填临时信息；用户可清空并看到影响范围。
- 网络断开：症状提示与当地电话仍可见；不可用功能不伪装可用。
- 拨号能力失败/用户取消：回到页面并显示手动拨号入口；不重复弹框、不宣称已拨出。
- 大字/窄屏：主按钮不被挤出首屏；布局单列，滚动只发生在页面内容区域；正文不小于16px。
- 键盘：焦点顺序先呼救，再识别提示，再交接输入；焦点有清楚标记。
- 减少动效：不使用倒数、闪烁、自动滚动或阻止退出的动画。

急症页面在医院、派车规则或网络服务无数据时应仍能执行手动求助。上述内容是原型合同草案，不是已预览/签认结果。
