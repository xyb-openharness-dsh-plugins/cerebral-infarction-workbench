# 场景与取舍（M1 草案）

状态：由本次任务授权开展的初始设计；没有真实用户签认。优先级先以安全与时间敏感度定性排序，不以定量打分冒充发生率。

## 场景详述

### S1：突发症状，立即求助

- 主体：本人、目击者或照护者。触发：任何突发脑神经功能异常，FAST 或其他新发异常；短暂好转也适用。
- 入口：首页首屏固定“疑似卒中？立即联系当地急救服务（中国大陆 120）”。点击后优先唤起电话/复制号码；不可保证宿主拨号时显示号码。
- 最少输入：无需输入即可看到呼救指引；可选“我正在呼救/已呼救”状态，不做确诊判断。
- 产物：呼救入口与简短 handoff 清单。失败恢复：网络断开仍本地展示静态信息；无定位/电话能力时显示当地号码与手动拨打提示。
- 成功观察：用户能在未填写资料前到达呼救动作；真实急症收益须后续观察，原型不能证明。

### S2：院前交接准备

- 输入：症状和时间（未知可标“未知”）、最早发现/最后正常（如知）、目击人联系方式（可略）、既往病史/过敏/现用药（只做清单，不提供用药动作）。
- 操作：跳过缺失项；用户可口述给急救人员；一键复制简短文本为备份。无需创建永久病历。
- 产物：带生成时刻与“由本人/照护者提供，未经核实”标记的交接卡。
- 失败恢复：单项输入失败/离开不清空其他内容；拒绝分享仍可口述；不要求上传报告或云服务。

### S3：稳定后的脑梗死资料整理

- 触发：本人/照护者出院后整理复诊材料。
- 输入：确诊机构/日期（可未知）、出院记录、影像/检验等文件索引、既有医嘱原文、用户问题；医学文档以原件和来源为主。
- 产物：日期线、原件来源索引、待问团队的问题草稿；AI内容只作为候选，用户核对后才保存。
- 边界：不推断梗死部位、机制、药物或治疗适合性；不把未检验/缺失写成阴性。
- 失败恢复：可离线整理；文件/目录无权限时提示而不删原件。
