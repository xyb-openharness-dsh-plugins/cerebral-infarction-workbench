# 设计者章程（M1 草案）

状态：由用户派单授权范围继承，产品取舍仍待用户晨审追认；不代表患者或临床签认。

- **代表谁**：疑似急症者、脑梗死患者本人及当时在场的目击者/照护者；本人优先，照护者可代为记录但不能默认获得长期访问权。
- **已明确**：目标病种脑梗死；这是队列首个急症工作台；M1/M2/M4 聚焦溶栓/取栓时间窗、分诊/院前处置、FAST识别与就诊准备；禁止真实患者数据入仓；只用公开来源和合成数据；不作疗效承诺、不提供用药建议；品牌暂用占位并待用户追认；M7/M8只备稿不发布。
- **成功结果**：怀疑卒中时不让产品造成求助延迟；患者/照护者能准备简明、来源可辨的信息交接；稳定后整理可追溯资料与复诊问题。
- **范围/地区**：中文界面、默认中国大陆语境；“120”须作为部署地区配置并核实。病种包括脑梗死，但急症入口处理的是“疑似卒中”，不尝试区分脑梗死与脑出血。儿童、孕产妇、卒中模拟病等专业急症路径待专家审核，不自行扩写规则。
- **研究证据**：指南/官方公共健康资料仅约束医学边界；患者研究支持任务假设，不推断发生率；无真实访谈即明示未做；记录来源、版本、地区、访问日和局限。
- **医学/AI边界**：急症入口先呼救；不输出是否适合溶栓/取栓、药物方案、等待建议或诊断。AI仅可把用户文本整理成待确认候选；急症不要求AI在线。
- **取舍原则**：安全与“不延迟求助”优先；缺少地方急救数据时不推荐具体医院；复杂病史不阻塞急症入口；资料完整性与患者操作负担之间优先可跳过/未知。
- **协作节奏**：按场景→交互路径→HTML原型→用户确认→schema冻结/生产实现；确认仅覆盖明确版本与功能。用户明确授权的G1自动签认标“待晨审追认”。
- **实际审查能力**：本轮模型为 Codex GPT-6（运行时模型标识可见、推理档位未提供）；非独立审查，独立临床/患者评审待完成。未发现本地 ai-spec 技能，不能宣称调用。
- **下一未决关键问题**：暂无产品问题影响当前原型构建；M2原型完成后，请用户对具体HTML版本/hash和一期模块范围签认后才进入生产实现。
